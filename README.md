# cfire

Терминальный симулятор горящего камина — красный/оранжевый аналог классического `cmatrix`.

## Готовые сборки

В разделе **Releases** этого репозитория на GitHub выкладываются готовые бинарники под **64-битную Windows** и **Linux x86_64** (GNU). Перед сборкой в CI выполняются `cargo fmt`, Clippy (в режиме предупреждений как ошибок) и тесты.

Релиз публикуется:

* при push **git-тега** вида `v*` (например `v0.2.0`), если помеченный коммит входит в историю ветки `master`;
* вручную: **Actions** → workflow **Release** → **Run workflow** на ветке **master** с полем **release_tag** (имя тега, например `v0.2.0`).

Скачайте `cfire-x86_64-unknown-linux-gnu` или `cfire-x86_64-pc-windows-msvc.exe`. На Linux при необходимости выставьте права на выполнение (`chmod +x`) и запускайте из терминала.

## Запуск

```bash
cargo run --release
```

Выход: латинская **q** или русская **й** (та же клавиша в ЙЦУКЕН). На **Windows** используется физическая клавиша **Q** (`VK_Q`), на **Unix/macOS** — поток UTF-8 из stdin (латиница и UTF-8 «й»/«Й»).

При завершении отдельная строка **не печатается**: восстанавливаются режим ввода (Unix **termios**, Windows консоль stdin), затем сброс стилей ANSI (`ESC [ 0 m`), показ курсора и очистка экрана — остаётся пустое окно для промпта shell.

### Режим блокировки экрана (как `cmatrix -L`)

```bash
cargo run --release -- --lock
# или
cfire -L
```

В этом режиме выход по **q** отключён; обработчик **Ctrl+C** игнорируется (Unix и Windows). Завершить процесс можно из **другого** терминала или SSH-сессии: `kill <PID>` (PID напечатан в stderr при старте), или закрыть окно терминала на Windows.

Обычный запуск без `-L` завершается **q** / **й** (см. выше).

## Что внутри

* **Автоопределение размера терминала** — огонь использует **всю высоту окна**; нижний ряд углей совпадает с нижней строкой терминала. После выхода экран очищается без лишнего текста — видно только приглашение shell.
* **Клеточный автомат**, вдохновлённый алгоритмом Fire из IBM 1984 года:
  тепло поднимается снизу вверх (updraft); охлаждение и случайное затухание зависят от **высоты над углями** (языки тянутся почти к верху).
* **Профиль топлива** — широкое «дно» для углей и узкий высокий центральный пик; в симуляции к верху экрана пламя **сужается конусом** (шире у основания, выраженный шпиль в середине), а не равномерная «решётка» как у мангала.
* **Convection columns**: в горячем восходящем потоке усиливается подъём, сильнее в центре экрана — длинные языки в середине, короче у краёв.
* **Ветер**: смещение тепла по горизонтали в основном вдали от центра; середина остаётся острее.
* **24-битные цвета** (ANSI `38;2;r;g;b`): пепел → тёмно-красный → оранжевый → янтарно-белый.
* **Символы** (без сплошного блока U+2588 — он часто выглядит как «чёрная плитка`): `▓ ▒ ░ / \ | ~ · :` — в типичном Unicode-терминале.
* **Двойная буферизация сетки** — состояние клеток обновляется в отдельном буфере и передаётся через `mem::swap`, без лишних аллокаций на кадр (удобно по SSH и на медленных TTY).
* **Вывод**: каждый кадр пишется под одной блокировкой `stdout` (`io::stdout().lock()`), чтобы escape-последовательности и символы не перемешивались.
* **Кроссплатформенность**:
  * **Unix** (в том числе сессия по SSH и виртуальный TTY): raw-mode до запуска чтения клавиш (`libc::tcgetattr`), чтобы **q** обрабатывалась сразу; стандартные ANSI-последовательности.
  * **Windows**: для выхода без Enter отключаются построчный ввод и эхо; опрос консоли по **VK_Q** не зависит от раскладки. Также включается VT на stdout для цветов и escape-последовательностей.

## Зависимости

| Кристалл | Цель |
|----------|------|
| `rand` 0.8 | Случайность (физика огня) |
| `terminal_size` 0.4 | Автоопределение размера терминала |
| `libc` 0.2 | Raw-mode на Unix |
| `windows-sys` 0.59 (только Windows) | VT на stdout, посимвольный stdin, **ReadConsoleInput** / **VK_Q** для выхода, Ctrl+C в режиме `--lock` |
