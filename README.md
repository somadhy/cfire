# cfire

Терминальный симулятор горящего камина — красный/оранжевый аналог классического `cmatrix`.

## Запуск

```bash
cargo run --release
```

Нажмите **q** для выхода.

## Что внутри

* **Автоопределение размера терминала** — огонь занимает всё окно (минус 5 строк для shell-промпта).
* **Клеточный автомат**, вдохновлённый алгоритмом Fire из IBM 1984 года:
  тепло поднимается снизу вверх (updraft), охлаждается по высоте, случайно затухает.
* **Профиль топлива** (3 гауссовых холма) — имитирует кучу дров с более высокой и интенсивной серединой, что формирует выраженные конвекционные колонки.
* **Convection columns**: горячие столбцы (>170 heat) поднимаются с меньшим охлаждением, создавая отдельные длинные языки пламени.
* **Ветер**: случайные порки создают боковой наклон пламени.
* **24-битные цвета** (ANSI `38;2;r;g;b`): пепел → тёмно-красный → оранжевый → янтарно-белый.
* **Символы**: `█ ▓ ▒ ░ / \ | ~ ·` — все доступны в любом Unicode-терминале.
* **Двойная буферизация сетки** — состояние клеток обновляется в отдельном буфере и передаётся через `mem::swap`, без лишних аллокаций на кадр (удобно по SSH и на медленных TTY).
* **Вывод**: каждый кадр пишется под одной блокировкой `stdout` (`io::stdout().lock()`), чтобы escape-последовательности и символы не перемешивались.
* **Кроссплатформенность**:
  * **Unix** (в том числе сессия по SSH и виртуальный TTY): raw-mode для неблокирующего ввода (`libc::tcgetattr`), стандартные ANSI-последовательности.
  * **Windows**: фоновый поток чтения `stdin` для выхода по **q**; при старте включается режим виртуального терминала (`ENABLE_VIRTUAL_TERMINAL_PROCESSING`), чтобы truecolor и управляющие последовательности корректно обрабатывались в консоли.

## Зависимости

| Кристалл | Цель |
|----------|------|
| `rand` 0.8 | Случайность (физика огня) |
| `terminal_size` 0.4 | Автоопределение размера терминала |
| `libc` 0.2 | Raw-mode на Unix |
| `windows-sys` 0.59 (только Windows) | Включение ANSI / VT в консоли Windows |
